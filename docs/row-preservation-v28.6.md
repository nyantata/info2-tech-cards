# GAS v28.6：既存行の保全

## 対象と公開範囲

既存ログ・画像・先生回答の保全を優先し、私有GASの保存処理と手動の行整理だけを修正します。
公開PRにはテスト・模擬環境・説明のみを含めます。GASソース全文は提供元へ差し替え用ファイルとして返却し、公開リポジトリには追加しません。
本番のスプレッドシート・Drive・デプロイはこの作業では操作しません。
ユーザーの方針により、別のGoogle検証環境は作成せず、架空データを使うローカルモックで確認します。

## 修正内容

- 新規ログは全列の最終使用行の後へ追記し、主要3列が空の既存行を再利用しない。
- 新規提出時に既存行を `clearContent()` しない。
- 提出処理はスキーマ確認より前にスクリプトロックを取得し、行整理と共通のロックを使う。
- 手動の `compactSubmissionLog()` は全体の消去・再書き込みを行わず、値・数式・セルのメモが完全に空の行だけを下から削除する。
- 追加列と最右列のメモも確認し、ゼロ、false、空白文字、結果が空文字の数式を空行扱いしない。
- 行整理の途中に失敗してもデータ行の消去・書き戻しを行わず、ロックを解放する。
- 提出番号・送信識別子・画像ファイルID・先生回答の管理方法と、既存フロントのAPIを維持する。

通常の提出に行整理は不要です。空行が途中に残っていても正常です。
行整理で行番号は変わりますが、画像は提出番号で紐付くため、その対応は維持されます。
行番号に依存する外部参照や手動の運用がある場合は、行整理を実行せず追記だけを利用してください。

## ローカル実行

受領したv28.5を `.private/gas-v28.5.gs`、返却用v28.6を `.private/gas-v28.6.gs` に置きます。
v28.5の基準コピーは書き換えません。

```sh
npm test
npm run test:row-fix
npm run test:row-fix -- --strict
```

別の候補ファイルを使う場合は `INFO2_GAS_SOURCE` で指定します。
対象ファイルは私有のまま維持し、Gitへ追加しないでください。

修正版でKI-02・KI-03を通常の回帰テストへ切り替えます。
元のv28.5に対しては引き続き既知の失敗として再現し、テストのassertを緩めて問題を隠しません。
行保全の追加6件は `test:row-fix` 時に実行します。私有ソースのない公開CIでは未実行と明記します。
残るKI-01・KI-04・KI-05・KI-06・KI-07は今回修正しません。

ローカル結果は、修正版が28件合格・5件TODO（未実行0件）、元のv28.5が20件合格・7件TODO・修正版専用6件未実行です。
修正版のstrict実行では28件合格・5件失敗となり、残件を再現します。
私有ソースなしの公開用コピーでは7件合格・25件未実行・1件TODOで、GASの合格を示す結果ではありません。
返却用Code.gsのSHA-256は `d1f65663a70d5edc6f7c72baa5bd07a6b28e6496e0d36ff5626a0a1bebe652fb` です。

## 確認対象

既存の36名提出、認証拒否、本人限定履歴、画像の再送回復に加え、次を確認します。

- 途中の空行、先生回答だけの行、追加列のある行を新規提出が変更しない。
- 数式、ゼロ、false、空白文字、最右列のメモが行整理後も残る。
- 完全な空行だけを下から削除する。
- 行整理が途中失敗してもデータ行とロックの状態を保つ。
- 行整理前後で本人履歴HTML・添付管理行・DriveファイルIDが一致する。
- 行整理の再実行が変更を起こさず、整理後の再送も重複を作らない。

Google実サービスの同時送信・数式参照の調整・共有権限・iPad実機は未検証です。
モックのロック検査は、実サービスでの並行処理保証を意味しません。

## 反映と復元

提供元へ渡す同梱手順に沿い、コードとスプレッドシートのバックアップを取ってから、既存デプロイを新バージョンへ更新します。
URL・スクリプトプロパティ・マニフェスト・GitHub Pagesの設定変更は不要です。
`compactSubmissionLog()`、`diagnoseStorage()`、診断URLの実行は更新手順に含めません。
問題があればバックアップしたコードで既存デプロイを更新するか、デプロイ管理で旧バージョンを選択します。
コードを戻しても行削除を元に戻すことはできないため、手動の行整理前には別途スプレッドシートをバックアップしてください。
