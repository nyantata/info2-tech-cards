# 段階1：ローカル回帰テスト

## 対象と影響

基準は `main` の `1e4074b83582ac0dff930dcbf761ba60225d2778` と、教員から提供された本番同等のGAS v28.5です。
この変更は検証用コード、架空データ、公開前チェック、CIのみを追加します。
既存HTML・assets・学校固有設定は変更しません。GASのデプロイ、スプレッドシート、Driveの操作もしません。

GASソースは公開PRに含めません。ローカルのみの `.private/gas-v28.5.gs` に受領ソースの未変更コピーを置きます。
別の私有ファイルを使う場合は `INFO2_GAS_SOURCE` でパスを指定します。ファイルをGitに追加しないでください。
SHA-256は `3c5884197898a1cbb703255dbb08bf6430d6e971f7f85b306908da988019b439` です。
将来の修正版は別ファイルとして検証し、この基準コピーを黙って更新しないでください。

## 実行

Node.js 22以上とGitを使用します。追加パッケージ・Google認証・実データは不要です。
GASの検証には上記の私有ソースが必要です。Googleへ接続するための環境変数は使いません。

```sh
npm run check
npm run test:strict
```

私有ソースありの通常実行は20件合格、7件TODOです。TODOは安全上望ましい動作をassertし、現在のコードで失敗する既知の問題です。
「27件すべて合格」という意味ではありません。strict実行はTODO扱いを解除し、現状では7件失敗して終了コード1になります。
公開CIでは私有ソースを渡さず、GAS関連19件を明示的にskipします。残りは7件合格、フロント側の既知問題1件TODOです。
このCI成功はGASの検証成功を意味しません。PRにはローカルのGAS検証結果も別途記載します。
未修正の問題を隠すためにassertを削除しないでください。修正PRでは対応するテストを通常の回帰テストへ移します。

テストランナーは日本時間に固定します。架空36名は3K01～3K36、メールは予約済みの `.invalid`、Google識別子は合成値です。
学年度2026はテスト用の値であり、認証・名簿機能を実装したものではありません。
パスワードや実際のGoogleアカウント対応名簿は含みません。

## 保護する既存動作

- 36名の提出、トークンからの提出者決定、認証エラー時の保存拒否。
- 自分の本文・画像・先生回答だけを表示し、HTMLをエスケープする。
- 同一送信の再実行で提出番号・画像・先生回答を保持する。
- Driveファイル作成後に共有が失敗した場合、再送で同じファイルを再利用する。
- 画像本体を監査JSONへ入れず、画像件数・日付・形式を検証する。
- 数式開始文字を無効化する。
- 15カードのID、JavaScript・JSONの構文、ローカル参照先を検査する。

## 既知の失敗と次の修正範囲

| ID | 再現する問題 | 修正時の確認点 |
| --- | --- | --- |
| KI-01 | 診断GETがアプリ内の教員認可なしでDriveを変更 | 診断の権限制御、読み取りと書き込みの分離 |
| KI-02 | 主要3列が空の行に残る先生回答を新規提出が消去 | 行全体の保全、追記方式、バックアップ |
| KI-03 | 行整理が主要3列の空行に残る先生回答を破棄 | 不明な行の隔離・停止、ロック、復元 |
| KI-04 | 同一送信IDで変更した本文を保存せず成功扱い | 内容ハッシュ・競合応答の契約 |
| KI-05 | 再送を繰り返すと同一提出の画像が3枚を超過 | 保存済みを含めた総数・総容量の制限 |
| KI-06 | 履歴表示でスキーマが書き換わる | 読み取りと管理者による移行の分離 |

各問題の修正は本PRに含めません。特に行整理、診断URL、`diagnoseStorage()`は本番でテスト目的に実行しないでください。

## モックの範囲

GASをVM内で実行し、Sheet、Drive、ロック、トークン確認をメモリ内の代替実装へ接続します。
トークン確認もHTTP通信はせず、許可したtokeninfo呼び出しを合成応答へ置き換えます。
実際のGoogle署名検証、ドメイン公開設定、共有の継承、GASの実行時間・容量制限、同時実行は検証できません。
ロック解放は確認しますが、モックによる逐次処理は並行送信の保証にはなりません。
Canvas、iPad、Googleログイン、画像圧縮の実ブラウザ試験も別途必要です。
次の結合確認には本番から独立した専用GAS・Sheet・Driveを使用します。

## 公開前チェック

```sh
npm run hooks:install
git add <今回の変更ファイル>
npm run check:public
node scripts/check-public-files.mjs --staged
```

フック導入は各開発者のローカルGit設定です。コミット・PRの前に実行してください。
`--staged`はGitインデックスの内容を検査し、作業ファイルだけを無害化する回避を防ぎます。
`.gitignore`は認証表・私有作業フォルダの誤追加を抑制します。
内容検査は改名した生徒認証表、体験用認証情報、秘密値の直書き、今回の私有GASソースの混入を検出し、値を出力せずに失敗します。
OAuth公開クライアントIDとGAS URLは秘密値として扱いません。学校固有の `assets/gas-config.js` は維持します。

検査は既知の書式に対する補助です。手動アップロード、フックの省略、未知の書式を完全には防げません。
CIはpush後なので、公開リポジトリへの初回流出を取り消す機能ではありません。実データ・認証情報は最初からリポジトリ外に保持してください。
すでに追跡済みのファイルにはgitignoreだけでは効かないため、ステージ内容検査とPRレビューを併用します。

## レビューと戻し方

機能ブランチ・PRでレビューし、本番変更や自動マージは行いません。
元のHTML・JS・CSS・設定と差分がないこと、提供された認証表・CSV・v3/v30試作品が混入していないことを確認します。
テスト基盤を戻す場合はこの追加コミットをrevertします。本番データの移行・巻き戻しは発生しません。
